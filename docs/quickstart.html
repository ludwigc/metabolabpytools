Quickstart · metabolabpytools

Predicting isotopomer distributions from HSQC + GC‑MS data

Train one small neural network per HSQC vector, then use it to predict the isotopomer distribution of a measured metabolite. Two ways to run it: notebooks for a walkthrough, or the command line for one-shot runs.

isotopomerAnalysis · 13C tracing workflow

Quickstart How it works →

1Set up

From the repository root, install the package into your environment. This also registers the mlp-train and mlp-predict commands.

# one-time, from the repo root
pip install -e .
Dependencies — installs numpy, scipy, pandas, openpyxl, tensorflow, keras-tuner, scikit-learn, matplotlib and seaborn. Python 3.9+ is recommended. A virtual environment (e.g. the project’s .venv) keeps this isolated.

2Know your inputs

Everything is keyed to an HSQC vector — one digit per carbon, 1 if that carbon is observed in HSQC, 0 if not (e.g. lactate is 0 1 1). A model is trained per vector. Prediction needs two spreadsheets: an HSQC multiplets file and a GC‑MS file, each with one sheet per metabolite.

InputWhat it is
--hsqc-vectorWhich carbons are HSQC-visible, one digit each.
--hsqc-dataHSQC multiplets spreadsheet (hsqcData1.xlsx), one sheet per metabolite.
--gcms-dataGC‑MS fragment percentages (gcmsData1.xlsx), one sheet per metabolite.
--metaboliteThe sheet name to analyse, e.g. L-LacticAcid.

3Train, then predict

Option A · Notebooks

A guided walkthrough

In metabolabpytools/jupyter/:

  • Open 01_train.ipynb, set hsqc_vector, Run All — simulates data, trains a seeded model, and keeps it if it beats the saved best.
  • Open 02_predict.ipynb, set the same vector and metabolite, Run All — it auto-loads the current best model and writes a results file.
Option B · Command line

One command each

Run from metabolabpytools/jupyter/ (where the example data lives), or add --work-dir <path>.

# train a model for one vector (deterministic; --seed default 42)
mlp-train --hsqc-vector 0 1 1

# predict on measured data (auto-loads the current best model)
mlp-predict --hsqc-vector 0 1 1 \
  --hsqc-data hsqcData1.xlsx \
  --gcms-data gcmsData1.xlsx \
  --metabolite L-LacticAcid
The number of training samples scales with carbon count automatically (10k for ≤3 carbons, 20k for 4, 40k for 5); override with --n-distributions.

3½Reproducible & keep-best

The dataset is simulated from a fixed seed and --seed (default 42) fixes the training run, so the same command always yields the same model. Each run is scored on a held-out test set and only replaces the saved model if the test MAE improves — so the file on disk is always the best found, and predict always uses it.

# search for a better model by sweeping seeds; the best is kept automatically
for s in 1 2 3 4 5; do mlp-train --hsqc-vector 0 1 1 --seed $s; done

mlp-train --hsqc-vector 0 1 1 --seed 7 --force   # overwrite even if not better
Labelled-only (optional) — add --labeled-only to both commands to fit only the labelled isotopomers (the dominant unlabelled peak is dropped and recombined from GC‑MS on predict). In a 5-seed test this improved the labelling pattern by 11–27%. See How it works.

4Where results land

Written relative to your working directory:

saved_models/the trained .keras model
model_summaries/architecture + held-out test MAE/MSE (used for keep-best)
sim_data/the simulated training data (kept for reference)
nn_analysis_results/predictions vs. back-calculated data

Good to know

  • Training is fast — seconds for 3-carbon, a few minutes for 5 — so retrain freely to iterate.
  • Accuracy is excellent for 3-carbon metabolites (~0.5% MAE) and settles near ~1% for 4–5 carbons, which is a limit of the measurements rather than the model.
  • Every prediction returns a per-isotopomer uncertainty (a standard deviation from Monte-Carlo dropout) alongside the mean.
  • Runs are reproducible — a fixed data seed and --seed make training deterministic, and the best model is retained across runs.

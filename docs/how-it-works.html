Recovering 13C isotopomer distributions from NMR + MS

A tour of the isotopomer-analysis pipeline: what the data means, how the network is trained on simulation, how predictions come with uncertainty, and where the classical fitting route fits in.

Package overview · metabolabpytools.isotopomerAnalysis

The problemWhat we’re trying to recover

In a 13C tracing experiment, a labelled substrate is fed to cells and its carbon spreads through metabolism. Each metabolite ends up as a mixture of isotopomers — copies of the molecule differing in which specific carbons carry a 13C label.

An n-carbon metabolite has 2n possible isotopomers (each carbon is labelled or not). The goal is the full distribution — the fraction of molecules in each of those 2n states — because that pattern encodes which metabolic pathways were active. We never measure it directly; we infer it from two complementary experiments:

  • HSQC NMR multiplets — for each HSQC-visible carbon, the fine structure of its peak reports whether neighbouring carbons are also labelled (via 13C–13C coupling). This gives local, position-resolved information.
  • GC‑MS — the mass-isotopomer distribution tells you how many carbons are labelled in total, but not which ones.

Neither alone pins down the distribution; together they constrain it. The HSQC vector (e.g. 0 1 1) records which carbons are observable in HSQC — carbon 1 of lactate, for instance, is a carboxyl and isn’t seen.

The pipelineFrom simulation to prediction

Rather than fit each sample from scratch, the tool learns the inverse map (measurements → distribution) once per HSQC vector, by training a network on simulated data where the true answer is known.

1 · Simulating training data

generate_isotopomer_distributions() builds thousands of synthetic samples. For each: every one of the 2n isotopomers is included by a coin flip (the unlabelled state always in), the unlabelled fraction is drawn between 30–100%, and the remainder is split randomly across the included isotopomers so the whole thing sums to 100%.

Each distribution is then pushed through the same forward model used by the classical fitting code (sim_hsqc_data / sim_gcms_data), which turns a known distribution into the HSQC multiplet percentages and GC‑MS percentages it would produce — including natural 13C abundance (1.07%) and the n-bond coupling range that decides which neighbours show up in a multiplet.

2 · Features and labels

VectorWhat it holdsBuilt by
X (input) HSQC multiplet percentages, zero-padded against every possible multiplet for this vector, concatenated with the GC‑MS percentages. collate_x_labels_*
Y (target) The full 2n-length isotopomer distribution (percent in each state). collate_y_labels

Feature ordering is canonical and shared between training and inference (create_feature_vectors reuses the exact same multiplet order), so the model sees inputs the same way in both. A small amount of Gaussian noise can be added to X to mimic measurement error.

3 · The network

Input(dim = #HSQC-multiplets + #GC-MS-channels)
  → Dense(128, relu) → Dropout(0.05)
  → Dense(64,  relu) → Dropout(0.05)
  → Dense(2ⁿ, relu)
  → NormalizationLayer            # non-negative, rescaled to sum to 100
loss = MSE   ·   optimizer = Adam(1e-3)   ·   early stopping on val_loss

It’s deliberately small. A Bayesian hyperparameter search (tune_model, still available) kept converging on a 1–2 layer network with little regularization, so the fixed architecture above matches its accuracy while training in seconds. The final NormalizationLayer guarantees every prediction is a valid distribution — non-negative and summing to 100.

4 · Prediction with uncertainty

At inference the two dropout layers are left active and the model is run n_iter times (default 200). This Monte-Carlo dropout yields a mean prediction and a standard deviation per isotopomer — the built-in uncertainty estimate. The prediction is then back-simulated into HSQC/GC‑MS space and written next to the real measurements so you can see how well it reproduces the inputs.

Why accuracy plateausA structural limit, not a modelling flaw

Below 4 carbons the problem is well-posed. At and above it, we try to recover more isotopomers than we have independent measurements — an underdetermined inverse problem, so part of the error is irreducible.

*The 5-carbon MAE looks lower only because many of its 32 isotopomers are near-zero and dilute the average; residual error concentrates on the least-constrained isotopomers (a few at ~2%), while the well-determined ones are already ~0.3%.

The ceiling is in the measurements, not the network A large unregularized network can’t fit even the training data below ~1% MAE (train 1.01% ≈ val 1.09%), and changing the loss, adding data, or standardizing inputs each moved accuracy by <0.1%. Raising it needs more independent measurements or fewer unknowns (biological priors) — see the meeting brief.

Two refinementsPrecision where it matters, and reproducibility

Labelled-only fitting

The unlabelled isotopomer is usually the largest component (often 60–90%). Fitting it alongside the small labelled species lets it dominate the loss. The --labeled-only mode drops it from the target, renormalises the labelled species to 100%, and recombines the measured unlabelled fraction (GC‑MS M+0) at predict time — so the network spends its capacity on the labelling pattern you actually care about.

Metabolite Labelling-pattern MAE
full → labelled-only		 Change
3 carbons2.37 → 1.72−27%
4 carbons3.69 → 3.19−14%

Mean over 5 seeds (±0.04–0.09). It improves the labelling pattern for every vector but does not beat the underdetermination ceiling — it reallocates precision to the labelled species rather than adding information.

Deterministic training and keep-best

The dataset is simulated from a fixed seed and --seed (default 42) fixes the training run, so the same command always produces the same model. Each run is scored on a held-out test set (separate from the early-stopping validation split) and only replaces the saved model when the test MAE improves — so the file on disk is always the best found, and predict always loads it. Sweeping seeds searches for a better model; the best is kept automatically.
